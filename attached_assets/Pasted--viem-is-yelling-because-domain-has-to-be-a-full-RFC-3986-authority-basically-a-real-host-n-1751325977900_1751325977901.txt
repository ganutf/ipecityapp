`viem` is yelling because **`domain:` has to be a full RFC 3986 “authority” (basically a real host-name)**.
The bare label **`justaname`** fails that check, so the message never even reaches JustaName’s servers.

### What to change

| field                                                           | replace with               | why                                         |
| --------------------------------------------------------------- | -------------------------- | ------------------------------------------- |
| `domain` (in the challenge request **and** in the SIWE message) | **`justaname.id`**         | passes the RFC 3986 test that `viem` does ★ |
| `uri`                                                           | **`https://justaname.id`** | keep the host consistent with `domain`      |

★ The relevant `viem` validation rule:

````ts
// viem@2.31.x  utils/siwe/createSiweMessage.ts
if (!domainRegex.test(domain))
  throw SiweInvalidMessageFieldError({
    field: 'domain',
    metaMessages: [
      '- Domain must be an RFC 3986 authority.',
      `Provided value: ${domain}`,
    ],
  })
``` :contentReference[oaicite:0]{index=0}

### Updated flow (concise)

```ts
// 1️⃣ Ask JustaName for a challenge
const { result: { data: { challenge } } } = await axios.post(
  'https://api.justaname.id/ens/v1/siwe/request-challenge',
  {
    domain : 'justaname.id',               // <<— fixed
    origin : 'https://justaname.id',       // <<— fixed
    address: userAddress,
    chainId: 1,
  },
);

// 2️⃣ Sign it
const signature = await wallet.signMessage(challenge);

// 3️⃣ Create the subdomain
await axios.post(
  'https://api.justaname.id/ens/v1/subname/add',
  {
    username : 'alice',
    ensDomain: 'ipecity.eth',
    chainId  : 1,
    addresses: [{ coinType: 60, address: userAddress }],
  },
  {
    headers: {
      'x-api-key'  : process.env.JAN_API_KEY,
      'x-address'  : userAddress,
      'x-message'  : Buffer.from(challenge, 'utf8').toString('base64'),
      'x-signature': signature,
    },
  },
);
````

Everything else (line-break escaping, base-64, etc.) stays exactly as before.

---

### Quick sanity checklist

1. **Same host everywhere** – `domain` **must** match the host part of `uri`.
2. **Don’t re-wrap** – once you have the `challenge`, do *not* modify its text before signing.
3. **Signer = ENS 2-LD owner** – the wallet that signs still has to own (or be an approved operator for) `ipecity.eth`.
4. **SDK makes this moot** – `@justaname.id/sdk` already uses `domain: 'justaname.id'`; swapping to the SDK side-steps this whole error.

Do those two string swaps and the **“Invalid Sign-In with Ethereum message field 'domain'”** toast disappears. 🎉
