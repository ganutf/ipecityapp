The JustaName API is rejecting the **SIWE** payload itself — the signature is never even checked.
Here’s what is going wrong and the quickest way to fix it.

---

### 1  Why the message is considered “invalid”

| ❌ What you signed (see screenshot)                                                             | ✔️ What the API expects                                                                                                                      |
| ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **Domain** line is your Replit preview host (`8084bd64-…replit.dev`).                          | Must be the literal string **`justaname`** (that is the `domain` you pass when you ask the API for a challenge). ([docs.justaname.id][1])    |
| The “Approve subdomain creation…” text is jammed on the same line as `URI:` (newline missing). | Every logical section has to be on its own **line** exactly as in EIP-4361 (blank line between statement → `URI:`). ([docs.justaname.id][2]) |
| You composed the message by hand.                                                              | The recommended flow is **request-challenge → sign → send**. That guarantees all field order, spacing, nonce, etc. are valid.                |

Any one of those mismatches triggers `SiweException: Invalid message`.

---

### 2  The “safe” flow (2 calls, zero guess-work)

```ts
import { ethers } from "ethers";
import axios from "axios";

const janKey   = process.env.JAN_API_KEY!;
const wallet   = new ethers.Wallet(process.env.PRIVATE_KEY!);  // must OWN the 2-LD
const address  = await wallet.getAddress();
const ens2LD   = "ipecity.eth";        // the parent you control
const subLabel = "alice";              // the sub you’re minting

// 1️⃣  Get an officially-formatted challenge
const { data: { result: { data: { challenge }}}} =
  await axios.post("https://api.justaname.id/ens/v1/siwe/request-challenge",{
    domain : "justaname",
    origin : "https://justaname.id",
    address,
    chainId: 1
  });

// 2️⃣  Sign the challenge *verbatim*
const signature = await wallet.signMessage(challenge);

// 3️⃣  Create the subname
await axios.post(
  "https://api.justaname.id/ens/v1/subname/add",
  {
    username : subLabel,
    ensDomain: ens2LD,
    chainId  : 1,
    addresses: [{ coinType: 60, address }]
  },
  {
    headers: {
      "x-api-key"  : janKey,
      "x-address"  : address,
      "x-message"  : Buffer.from(challenge, "utf8").toString("base64"), // safe header
      "x-signature": signature
    }
  }
);
```

*The challenge arrives already formatted, has the right `Nonce`, and says
“**justaname wants you to sign in with your Ethereum account:** …” exactly the way the verification code on the server parses it.*

---

### 3  Common pitfalls to avoid next time

1. **Domain / origin mismatch** – they must be `justaname` and `https://justaname.id`; your local dev host is not accepted.
2. **Mutating the message after signing** – escaping `\n` is fine **before** you sign, but if you change line breaks *after* signing the signature will no longer match.
3. **Wrong signer** – the wallet that signs has to be the owner (or delegated operator) of **`ipecity.eth`**; a random wallet with an ENS *sub*domain will fail later with `Forbidden`.
4. **Custom statements** – if you need a bespoke “Approve subdomain creation for …” line, insert it as the **single “statement” line** *between* the blank line and the `URI:` line, keeping the exact spacing.

---

### 4  Bonus: let the SDK handle everything

```ts
import { JustaName, ChainId } from "@justaname.id/sdk";

const jan = new JustaName({ apiKey: janKey, chainId: ChainId.Mainnet });
await jan.subname.add({
  username : subLabel,
  ensDomain: ens2LD,
  signer   : wallet            // SDK builds+signs SIWE, encodes headers
});
```

Under the hood the SDK does steps 1-3 (and the newline escaping) for you, so the **“Invalid message”** error simply disappears. ([docs.justaname.id][3])

---

**TL;DR** — Use `domain: "justaname"` when you request the challenge, sign the message exactly as delivered, send the *identical* string (escaped or Base-64) in the `x-message` header, and the subdomain will be created without the 403.
